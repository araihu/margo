## Objetivo P1

Implementar somente os contratos públicos e a identidade de plataforma do módulo `pdf`:

- `Engine`, `Request`, `Result`, `EngineInfo`, `ExportReport`;
- `PageConfig`, `PageSize` (`A4|Letter`), orientação, margens e validação;

WKWebView, WebKitGTK, Chromium/CDP ou orquestração `Export`; esses são P2–P7.

## Limites de proveniência

- Não criar `replace`, pseudo-versão, `go.sum`, proxy, tag, release ou identidade de
  plataforma fictícios.
- A dependência do root só pode usar uma identidade já verificável. Sem identidade
  I2/I3/proxy autorizado, registrar o bloqueio e manter o contrato em escopo, sem
  fabricar uma versão para fazer o módulo resolver.
- `chromedp` só entra com a versão/somas exatas do plano P1 e prova readonly.
- Native SDKs são host-provided; ausência de evidência torna runner indisponível,
  nunca motivo para baixar ou substituir binding.
- A lane é feature candidate. I2/I3 e aceitação formal de release continuam fora
  do escopo desta sucessão.

## Gates da nova lane

Antes de cada comando de módulo: `GOWORK=off GOFLAGS=-mod=readonly`, proxy autorizado
quando existir, snapshot/hash de `pdf/go.mod` e `pdf/go.sum`, e nenhuma mutação dos
arquivos durante teste ou geração.

Gate mínimo P1:

```sh
cd pdf
GOWORK=off GOFLAGS=-mod=readonly go test . -run 'Test(PageConfig|EngineContract|ExportReport|PlatformToolchain|RunnerContract|NoDownload)' -count=1
GOWORK=off GOFLAGS=-mod=readonly go mod verify
GOWORK=off GOFLAGS=-mod=readonly go list -deps ./...
GOWORK=off GOFLAGS=-mod=readonly go test ./platform -run 'Test(PlatformToolchainLock|RunnerContract|NoDownload)' -count=1 -args -lock platform-toolchain.lock -contracts platform/runner-contracts.json
```

Aceitação da lane exige testes RED/GREEN do plano P1, graph sem `replace`, probes
sem download, contratos imutáveis e `git diff --check`. Depois do commit, nova
reviewer deve recomputar HEAD/tree/status e revisar somente os paths acima.
