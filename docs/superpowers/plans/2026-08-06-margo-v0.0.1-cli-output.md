# Margo CLI and output contracts implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver thin `margo` commands over the same library pipeline with bounded staging, typed transactional filesystem outcomes, fully spooled stdout, deterministic diagnostics/reports, and authority-gated public HTML.

**Architecture:** Root module owns ArtifactSink, spool, atomic file primitives, classification, and digest-bearing CommitResult. `cmd/margo` assembles core/deck/charts/pdf extensions, parses CLI input/options, finishes validation/runtime/report construction into a private spool, then commits once to file or stdout.

**Tech Stack:** Go 1.26.5, root/charts/pdf modules, platform atomic rename/replace APIs, Cobra-free thin command dispatcher or standard flag sets, JSON diagnostics.

## Global constraints

- Repository/module stays `github.com/araihu/margo/cmd/margo`; binary stays `margo`.
- Commands are exact: `render`, `pdf`, `deck`, `validate`, `inspect`, `schema chart`, `doctor`, `version`.
- Commands accept one path or stdin. Artifact bytes use stdout or explicit destination; all diagnostics use stderr.
- `--diagnostics json` uses exact stable fields `code,severity,source,line,column,pointer,message,hint`.
- `render`/`deck` execute runtime tasks with native engine by default or explicit Chromium; HTML without browser tasks executes no engine.
- `pdf` defaults native. No command silently falls back or downloads Chromium/runtime assets.
- Every final artifact/report is complete in bounded memory/private spool before publication.
- Existing destination is refused unless `--force`. Filesystem success means only `committed`; uncertain/unknown outcomes are distinct nonzero errors naming possibly visible new bytes. No retry/delete/rollback.
- Private stdout/file HTML is default and contains no invented canonical/Open Graph/X URLs. `--publication public` requires a verified `--authority-record FILE|HTTPS_URL`; `--canonical-origin` is an optional equality assertion only and cannot approve a route. Public mode consumes the record's routes, owner/host/deployment evidence, receipt, and digest through Core C7.
- `margo render --engine native|chromium` is exact, defaults to `native`, and accepts Chromium only when an installed executable path/version is explicitly configured. Invalid, unavailable, or uninstalled Chromium fails before staging; no command downloads or falls back. The same flag contract applies to `pdf` and `deck`.
- No sidecar or asset tree is written by default. Batch/glob flags/commands stay absent in v0.0.1.
- Every nested command module test runs through the roadmap's exact `readonly_lane_command cmd/margo "$MARGO_CHECKED_GOPROXY"` or `readonly_lane_gate cmd/margo "$MARGO_CHECKED_GOPROXY"` scope. The displayed `GOWORK=off GOFLAGS=-mod=readonly` prefixes are payload notation, never direct ambient commands; the scope clears both proxy-variable cases and checks `cmd/margo/go.mod` and `cmd/margo/go.sum` before and after each command.
- Every readonly command-module, report, verifier, race, and integration command snapshots `cmd/margo/go.mod` and `cmd/margo/go.sum` with `git hash-object` and asserts both hashes are unchanged afterward; O5's named module-provisioning predecessor is the only writer.
- Release evidence has one schema and one producer/consumer flow. Each fresh task reviewer writes exactly its task-named file in `review/evidence/{C0,C1,C2,C3,C4,C5,C6,C7,C8,T0,T1,T2,T3,T4,T5,T6,M0,M1,M2,M3,M4,M5,M6,M7,H1,H2,H3,H4,H5,H6,P1,P2,P3,P4,P5,P6,P7,D1,D2,D3,D4,D5,O1,O2,O3,O4,O5,O6,O7}.json`; O7 validates those records with `cmd/margo/internal/releasecheck`; I4 alone writes the aggregate `release/evidence/v0.0.1.json`. No reviewer may write the aggregate or self-authorize its own record.
- `EvidenceRecord` fields are `schemaVersion:"margo/release-evidence/v1"`, `taskID`, `lane`, `commit`, `tree`, `reviewerIdentity`, `commands:[{argv,workingDirectory,environment,exitCode,platform,stdoutSHA256,stderrSHA256}]`, `artifacts:[{path,sha256,bytes}]`, `inputs:{authorityRecordPath,authorityRecordSHA256,homepageHTMLPath,homepageHTMLSHA256,representativeHTMLPath,representativeHTMLSHA256,previewFilePath,previewFileSHA256}`, `requirements:[Sxx|ACxx|SG01|AUTH01|HEAD01]`, and `status:"accepted"`. Public social evidence requires every `inputs` path and matching digest; private records omit publication inputs. The verifier rejects missing paths, unresolved IDs, changed commit/tree, omitted environment/working directory, non-zero exit evidence, absent/mismatched authority/downloaded HTML/image inputs, and any requirement outside the frozen ID set.
