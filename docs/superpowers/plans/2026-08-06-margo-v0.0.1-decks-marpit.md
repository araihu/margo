# Margo decks and Marpit compatibility implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add explicitly activated static Marpit-compatible decks with safe directives, Goshtoso document rendering, engine-decided overflow, one slide per PDF page, and social-ready public HTML.

**Architecture:** `deck` is a package in the root module. Its extension parses slide separators/directives/notes only in deck mode, reuses the root compiler/policy/render pipeline, emits semantic slide sections and a deterministic layout runtime task, then relies on accepted PDF layout engines before claiming visual validity.

**Tech Stack:** Go 1.26.5, Margo root extension/render APIs, templ, Goshtoso components, `margo-runtime/v1`, PDF layout engines.

## Global constraints

- Deck activates only by CLI `deck`, explicit deck option, or top-level `marp: true`. Ordinary Markdown keeps thematic breaks and no pagination.
- Supported global directives: `theme`, `lang`, `headingDivider`. Supported local directives: `paginate`, `header`, `footer`, `class`, `color`, background asset/position/repeat/size. `_` spot prefix is supported.
- Recognized directives parse structurally. Unknown comments become presenter notes; other comments follow raw HTML policy. `style` is recognized and rejected.
- Host allowlist owns class names. Colors, positions, repeats, sizes, dimensions, and AssetRef values use typed bounded policy; directive text is never concatenated into CSS.
- Default aspect is 16:9; 4:3 and bounded custom dimensions supported. No text shrinking.
- Output is `<article class="goshtoso-deck">` containing one semantic `<section class="goshtoso-slide">` per slide.
- Slides reuse ordinary Markdown, Goshtoso CodeBlock/Table, Mermaid, and registered supported charts. No interactive navigation, presenter mode, transitions, fragments, markdown-it plugins, arbitrary themes/CSS, or experimental inline SVG.
- Visual overflow is valid only after an accepted layout engine. Threshold is any excess beyond 1/64 CSS pixel.
- Public deck HTML uses Core C7 metadata ownership and authority-approved CanonicalOrigin. Private/local deck HTML omits canonical/Open Graph/X URLs.
- Core C7's `AuthorityRecord` is mandatory for public deck output. `--canonical-origin` or a route string alone is an assertion, never approval. Public initial HTML uses the verified record's route and preview path; no production domain is hardcoded.
- Root C0 provisions templ `v0.3.1020`; all deck generation command payloads run through the roadmap's exact `readonly_lane_command . "$MARGO_CHECKED_GOPROXY"` scope, with `GOWORK=off GOFLAGS=-mod=readonly` shown only as payload notation. The helper clears both proxy-variable cases and hashes root `go.mod`/`go.sum`. Browser overflow evidence uses Mermaid M0's pinned Playwright/Chromium harness; no bare Node DOM/test command is valid.
- Each readonly deck command snapshots the applicable module `go.mod`/`go.sum` hashes and asserts they are unchanged after the command; module-file changes return to the module owner.
