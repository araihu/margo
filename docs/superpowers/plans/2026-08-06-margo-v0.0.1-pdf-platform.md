# Margo PDF and platform engines implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `github.com/araihu/margo/pdf` with native-first PDF generation on Windows/macOS, explicit best-effort Linux, installed-Chromium opt-in, and accepted `margo-runtime/v1` readiness.

**Architecture:** PDF module accepts exact core standalone HTML, page/brand configuration, and RuntimeDescriptor. Each engine blocks network/navigation, injects a unique ExecutionID, collects and validates a terminal RuntimeReport, then creates PDF bytes. Orchestrator never falls back between engines and returns provenance without publishing output.

**Tech Stack:** Go 1.26.5, build-tagged WebView2/WKWebView/WebKitGTK bindings, Chrome DevTools Protocol, Margo core runtime/report types, native platform CI.

## Global constraints

- Module path is exact `github.com/araihu/margo/pdf`; it imports root only, never charts or CLI.
- `native` is default at CLI assembly. `chromium` is explicit and uses a configured or already-installed executable. No download/bundle/fallback.
- Windows uses WebView2 direct PDF creation; macOS uses WKWebView direct PDF creation; Linux WebKitGTK is best effort and reports unavailable/limitations explicitly.
- Wails v3 is architecture reference only, never a dependency or PDF abstraction.
- A4 and Letter, portrait/landscape, margins, same header/footer, watermark, page number, fonts, Mermaid, charts, long tables use one core HTML/CSS page model.
- Engine accepts only runtime report status `ready` with matching protocol, DocumentFingerprint, RenderInstanceID, ExecutionID, task set, assets, and no blocked request.
- Cancellation closes and reaps every browser/webview/process. Timeout, request, font, layout, task, asset, protocol, or identity error returns no PDF bytes.
- Engine report records document/artifact fingerprints, exact digest, engine name/version, runtime report, page config, compiler/theme/assets/warnings. Native PDF byte digest is not promised stable.
- Internal export HTML uses private publication mode unless caller supplied authority-approved public metadata; engine never invents canonical URLs.
- Run module gates from `pdf/` through the roadmap's exact `readonly_lane_gate pdf "$MARGO_CHECKED_GOPROXY"` scope; displayed `GOWORK=off GOFLAGS=-mod=readonly` prefixes are payload notation only. Each task-local command payload uses `readonly_lane_command pdf "$MARGO_CHECKED_GOPROXY"`, which clears both proxy-variable cases and hashes `pdf/go.mod`/`pdf/go.sum` around the command.
- Every readonly PDF module, platform, verifier, race, and integration command snapshots `pdf/go.mod` and `pdf/go.sum` with `git hash-object` and asserts both hashes are unchanged afterward; any mutation fails the gate.
- P1 owns exact `pdf/go.mod`/`pdf/go.sum` pins before any PDF consumer: root `github.com/araihu/margo` at the accepted I3 predecessor and `github.com/chromedp/chromedp v0.14.2` (`h1:r3b/WtwM50RsBZHMUm9fsNhhzRStTHrKdr2zmwbZSzM=`, go.mod `h1:rHzAv60xDE7VNy/MYtTUrYreSc0ujt2O1/C3bzctYBo=`). `GOWORK=off GOFLAGS=-mod=readonly go mod download`, `GOWORK=off GOFLAGS=-mod=readonly go mod verify`, `GOWORK=off GOFLAGS=-mod=readonly go list -m all`, and no-replace checks precede P2.
- P1 also owns `pdf/platform-toolchain.lock` and `pdf/platform/runner-contracts.json`. The lock schema is `margo/pdf-platform-toolchain/v1` and records Go `1.26.5`, the exact root and chromedp module versions/sums, runner IDs `windows-webview2/v1`, `darwin-wkwebview/v1`, `linux-webkitgtk/v1`, and `chromium-cdp/v1`, each runner's owned probe path, host SDK/runtime evidence path, source digest, and `networkPolicy:"no-download"`. Its `nodeHarness` reference names M0's locked Node `v26.5.0`, npm `11.17.0`, DOMParser/XMLSerializer/CSSOM plus css-tree strategy, Playwright `v1.52.0`, and Chromium revision `1169`/archive digest; its `muambaTool` reference names C0's `github.com/araihu/muamba/cmd/muamba@v0.0.3` tool directive. Native SDKs are system-provided rather than fetched; a runner is unavailable when its exact SDK/runtime identity is absent from evidence. Chromium uses only the installed executable/CDP runner and the Mermaid M0 browser lock is the sole browser/package provenance. No platform task may select an unrecorded binding, download a browser, or substitute a different runner.
